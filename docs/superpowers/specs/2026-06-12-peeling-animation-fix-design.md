# 剥橘子动画穿模修复 — 设计文档

> 日期：2026-06-12　·　状态：待评审　·　分支：feature/animation-update

> ⚠️ **方案已转向（2026-06-13）**：本文档描述的"穿透度加权外鼓贝塞尔"方案**已废弃**——实测外鼓观感怪异、
> 不如原版。最终采用 **`SphereGeometry(phiStart=-π/2)` 背面切口**（antimeridian crossing 解法）：
> 把网格接缝挪到背面，线性分割在背面干净发生（被前半球遮挡），正面光滑无穿模、平面图正确、无需外鼓。
> 详见 `CLAUDE.md`「背面切口」条目。本文档保留作历史记录（含根因分析、atan/线性/贝塞尔三方案权衡，仍有参考价值）。

## 1. 背景与问题

当前"剥橘子"展开动画在 `globe.vert:60` 用一句线性插值实现：

```glsl
vec3 finalPos = mix(spherePos, flatPos, localProgress);
```

每个顶点沿**直线弦**从球面位置走到平面投影位置。在 ±180° 接缝处这会产生穿模：

- 接缝是球背面的同一点（lon=±180° 都在 `x=−cosLat`，−x 侧）。
- 平面目标却在两端：Mercator `flatPos.x = lon`，+180° → `x=+π≈+3.14`，−180° → `x=−π≈−3.14`。
- 于是 +180° 列从 `x=−1` **横穿球体正面**走到 `x=+3.14`（"向内穿"），−180° 列从 `x=−1` 走向 `x=−3.14`（"向外包"）。
- 数值验证：赤道、滑块 30% 时 `localProgress≈0.40`，+180° 列顶点 x≈0.64 追平 lon=0 正面列 x≈0.60 → 网格自交，穿模峰值。

这不是真正的剥开，而是表面互相穿过，破坏"地球变平面"的科普表达。

## 2. 目标与非目标

**目标**
- 消除墨卡托 / 等距柱状 / 圆锥三种投影下剥橘子过程的表面穿模（自相交）。
- 保留现有"球面 → 平面投影"的连续变形手感与赤道先开、两极延迟的时序。
- 4 种投影统一路径公式（方位投影按其固有性质处理）。
- 表面"从球面外侧离开再落到平面"——视觉上是真·剥开，同时忠实呈现每种投影的映射。

**非目标**
- 不做"橘子瓣外翻"等拓扑重做（与投影对比教学目标冲突，详见 brainstorm 记录）。
- 不强求消除方位投影（正射/立体）的终态穿模——那是投影固有性质（见 §6）。

## 3. 方案：穿透度加权外鼓贝塞尔（修正后）

把直线 `mix(P0, P2, t)` 换成**二次贝塞尔曲线**，控制点把路径撑到球面外侧。经"确定性数值验证 + 对抗式独立验证"定稿，最终公式含三个必须修正项（缺一则不达标）：

```glsl
// 输入：P0=spherePos（单位球）, P2=flatPos, lat, lon（弧度）, t=eased localProgress, S=uPeelStrength
vec3  r      = normalize(P0);
vec3  d      = P2 - P0;
float dLen   = length(d);
float dGate  = smoothstep(0.0, 0.05, dLen);                 // 【修正①】d≈0（极点/正射南极）时 L→0

float dr     = dot(d, r);
vec3  dPerp  = d - dr * r;                                   // 位移的切向分量
float pen    = max(0.0, -dr);                                // 向内穿透深度

vec3  poleY  = vec3(0.0, lat >= 0.0 ? 1.0 : -1.0, 0.0);      // 退化分支：极轴 ±Y（赤道取 +1）
vec3  liftDir0 = length(dPerp) > 1e-3 ? normalize(dPerp) : poleY;

// 【修正②】接缝窄带 y 连续混合（|lat|<2° 且 |lon|>170°），不衰减 L
float latGate = 1.0 - smoothstep(0.0, 0.0349, abs(lat));      // 2°
float lonGate = smoothstep(2.967, PI, abs(lon));              // 170°
float yBlend  = latGate * lonGate;
vec3  liftDir = normalize(mix(liftDir0, poleY, yBlend));

float lonWeight = smoothstep(0.3, 1.0, abs(lon) / PI);        // 【锁定】阈值必须 [0.3,1.0]，抑制正面鼓包
float L    = S * (0.6 + 0.4 * pen) * lonWeight * dGate;
vec3  C    = P0 + L * liftDir;

vec3 peeled = mix(mix(P0, C, t), mix(C, P2, t), t);          // de Casteljau = 二次贝塞尔
```

**默认 `uPeelStrength = 1.5`，滑块范围 1.2 ~ 2.0。**（半径硬约束其实 S=1.0 即满足，1.5 为视觉/平滑裕度。）

### 三个必须的修正项

| 修正 | 原因 | 不加的后果 |
|---|---|---|
| **① d 门控** `dGate` | 极点 / 正射南极处 P0≈P2、d≈0、pen≈0，原公式仍给 `S·0.6` 鼓包，退化分支 ±Y 在南极指向球心 | 正射南极（la=−90°, \|lon\|≥120°）引入 **62 个新穿透单元**（baseline r=1.0 → 0.55）——主验证者与怀疑者均漏报 |
| **② 接缝窄带 y 混合** | 赤道接缝 `dPerp.y` 随 lat 翻号，任何外鼓都放大成尖刺 | 赤道顶点（lon=180,lat=0）在 t=0.5 产生孤立尖刺（crossDZ 双侧撕裂 3.19 / 3.19） |
| **③ 法线/切线重算**（见 §5） | 位置改贝塞尔后，原 `mix(sphereN, flatN, t)` 线性法线与鼓包几何夹角达 21°–69°，y 分量翻号 | 剥橘子中段错误高光带/黑斑，法线贴图凹凸方向错乱 |

### 退化分支：poleAxisY（废弃 crossDZ）

独立验证：crossDZ 在精确退化点 (lat=0, lon=±180) 给 liftDir=+Z，赤道顶点向 +Z 凸出，与南北两半各撕裂 3.19；poleAxisY 给 +Y，赤道顶点与北半邻连续（偏 0.004）仅南半侧撕裂 4.52。**poleAxisY 把"双侧尖刺"降为"单侧撕裂"，严格优于 crossDZ。**

### lonWeight 阈值锁定 [0.3, 1.0]

`smoothstep(0.3,1.0,|lon|/π)` 各经度权重：0°→0, 90°→0.20, 120°→0.54, 150°→0.86, 180°→1.0。**接缝（180°）权重=1.0 完全保留鼓包**（这正是穿模最严重的点）。不可上调到 [0.5,1.0]——独立验证该阈值在 lon=120° 清扫者边界把 L 压到使 minR=0.87，破坏不穿模保证。

## 4. 影响面：三处同步（半单源）

剥橘子数学在 3 处各有一份，必须同步：

| 文件 | 位置 | 作用 |
|---|---|---|
| `src/shaders/globe.vert` | `:60` 位置、`:63-64` 法线、`:85-86` 切线/副切线 | 地球本体变形 + 光照法线 |
| `src/shaders/indicator.vert` | `:67` 位置、`:80-83` 法线 | 朝索/面积/航线（GPU 投影路径） |
| `src/indicators/greatCircleRoutes.js` | `computeLabelPosition :238-242` | 城市精灵/发光粒子（JS 投影路径） |

- **GLSL 层**：把贝塞尔路径（含 d 门控、y 混合、lonWeight）抽成共享函数放入 `src/shaders/common/projections.glsl`，`globe.vert` 与 `indicator.vert` 经 `#include` 复用——改一处两处同步。
- **JS 层**：`greatCircleRoutes.js` 的 `computeLabelPosition` 必须逐项复刻贝塞尔路径（含三个修正项），否则城市精灵/发光粒子与 GPU 航线在剥橘子中段错位。这是现有"半单源"的延续。
- **护栏**：仿照 `scripts/glsl-lint.mjs` 现有的 clamp 边界断言，新增对贝塞尔关键常量（dGate 阈值 0.05、lonWeight [0.3,1.0]、latBand/lonBand）的 GLSL↔JS 一致性断言。`glsl-lint` 现有 clamp 边界护栏不覆盖路径形状，需扩展。

## 5. 法线/切线重算（修正③，最影响观感）

位置改成外鼓贝塞尔后，`globe.vert:63-64` 的 `mix(sphereNormal, flatNormal, t)` 与鼓包曲面严重失配（t=0.5 夹角 21°–69°，真法线 y 分量翻号）。**必须从贝塞尔曲面切平面重算法线与切线：**

```glsl
// 数值偏导（复用 indicator.vert:29 computeAreaDistortion 的有限差分模式）
float eps = 0.001;
vec3 pC   = peeledPos(lat, lon, t);            // 当前点（封装好的贝塞尔求值）
vec3 pLat = peeledPos(lat + eps, lon, t);
vec3 pLon = peeledPos(lat, lon + eps, t);
vec3 T_lat = pLat - pC;                         // 纬度切向 → 副切线
vec3 T_lon = pLon - pC;                         // 经度切向 → 切线
vec3 N = normalize(cross(T_lat, T_lon));        // 曲面法线
```

- **混合区间**：t∈[0.15, 0.85] 用重算法线/切线；端点（t<0.15 或 t>0.85）保持原 `mix` 线性插值，保证 C0 连续（球态与终态平面态法线不变）。
- **法线贴图 TBN**：`globe.frag` 中 `sphereBitangent` 的手性校正 `B = cross(N,T)*sign(dot(cross(N,T), vBitangent))` 需连带复核——外鼓段切线空间翻转会让凹凸反向。**实现时先做 A/B 截图对比**剥橘子中段光照，确认凹凸方向正确再定稿。
- **indicator.vert** 的插值法线（朝索/面积轮廓背面剔除用）精度要求低，可暂保持线性；但 `globe.vert` 的光照法线必须重算。

> 注：`easeInOutCubic` 让动画大部分时间停在 t≈0/1 端点附近，中段（t=0.5 鼓包峰、法线误差最大处）屏幕停留短——减轻视觉影响，但用户可暂停在任意 t，故仍必须重算。

## 6. 各投影状态（验证结论）

| 投影 | 状态 | 最小安全 S | 说明 |
|---|---|---|---|
| 墨卡托 | ✅ 修复（含残留） | 1.0 硬约束 / 默认 1.5 | 清扫者全程半径≥1、penetrateCount=0、端点精确。赤道接缝单顶点南半侧撕裂（见 §7 残留①） |
| 等距柱状 | ✅ 修复 | 1.0 / 1.5 | 与墨卡托同构，无赤道自交 |
| 圆锥 | ✅ 修复（含残留） | 1.0 / 1.5 | 清扫者半径满足；赤道有 2D-XY 自交伪影但 3D z 分离（见 §7 残留②） |
| 方位-正射 | ⚠️ 投影固有 | 不适用 | 加 d 门控后 ≈ baseline（不回退）；终态 \|P2\|=0.08<1 不可消（见下） |
| 方位-立体 | ⚠️ 投影固有（更优） | 1.2 | 方案 B 严格优于 baseline（穿透单元减半），逐顶点零回退；极点终态 \|P2\|=0.17<1 不可消 |

**方位投影说明（措辞经独立纠正）**：正射把背面半球压到正面圆盘中心 `P2=(0,0,−0.08)`；立体把极点钳到 1.4 后映到对侧 `P2=(0,−0.171,0)`——两个端点都落在单位球内，因 t=1 终点固定=P2，任何以 P2 为终点的路径在 t→1 必穿模，增大 S 仅推迟起始 t 不能消除。**这是投影固有，方案 B 不构成回退**（正射持平、立体更优）。缓解建议（可选，非必须）：方位投影剥橘子进行时 UI 隐藏/裁剪背面顶点。

> **更正**：主验证脚本初报"方位投影赤道恒自交"为**误报**——独立 1° 细网格验证两投影赤道自交恒为 0（原检查器把 lon=±180 闭合端点重合误判）。验收标准保留"赤道不自交"（方案 B 满足），删除"现状会自交"的断言。

## 7. 验收标准

1. **不穿模（核心）**：墨卡托/等距柱状/圆锥下，`uPeelStrength∈[1.2,2.0]` 时所有 \|lon\|≥120° 的"清扫者"顶点全程（t∈[0,1]）半径 ≥ 1（用 `scripts/peel-verify.mjs` 1° 网格复核，penetrateCount=0）。
2. **赤道 3D 不自交**：赤道空间折线在剥橘子全程无非邻接段相交（判定标准是 **3D 空间曲线**，非 2D-XY；圆锥的 2D-XY 伪影不计）。
3. **端点精确**：B(0)=P0（球面）、B(1)=P2（平面），`endpointMaxErr=0`。
4. **法线正确**：剥橘子中段（t≈0.5）无错误高光/黑斑，法线贴图凹凸方向与球态一致（A/B 截图确认）。
5. **三处同步**：城市精灵/发光粒子与 GPU 航线在剥橘子中段不错位。
6. **正射南极不回退**：加 d 门控后，`scripts/peel-verify.mjs` 在正射 la=−90°、\|lon\|≥120° 的穿透单元归零。
7. **GLSL 通过 `pnpm lint:glsl`**，且新增的贝塞尔常量护栏断言通过。

## 8. 已知限制与残留风险

1. **赤道接缝单顶点撕裂**（lon=±180, lat=0）：poleAxisY + y 混合把 crossDZ 的双侧尖刺（3.19/3.19）降为单侧撕裂（南半侧 4.52，与北半连续偏 0.002）。根因是 `dPerp.y` 在 lat 过 0 翻号为赤道接缝几何固有，360×180 网格下仅 1–2 个顶点。彻底消除需对该列用专门对称路径（**本期不做，标注为已知**）。
2. **圆锥赤道 2D-XY 自交**：剥橘子全程（t>0）存在，但交叉对在 z 上分离 ~2.0（3D 真实距离≈2.0，非真自交）。3D 渲染下不可见；若后续把赤道环/朝索作 2D 屏幕空间叠加层会看到——需限定或标注。
3. **正射/立体终态穿模**：投影固有，不可消。S 对这两个投影仅推迟起始 t。立体 S≥2 后穿透饱和 ~84，继续增大无收益——滑块上限 2.0，勿误导用户。
4. **法线重算未在真实 TBN 管线验证**（仅数值算角度）：实现时必须 A/B 截图对比。混合区间 [0.15,0.85]、dGate 阈值 0.05、latBand 2°/lonBand 170° 均为经验值，需实机微调。
5. **方位投影背面重叠**：正射前后半球压同盘、立体极点钳位——剥橘子终态示意图层面可接受（用户预期重叠）；如需更干净，UI 层在剥橘子进行时裁剪背面顶点。

- `scripts/peel-verify.mjs`（本期新增）：5 投影 × (lat,lon,t) 网格，检查端点精确、清扫者半径≥1、赤道 3D 不自交、正射南极回归。调 `uPeelStrength` 时复跑。

---

**验证依据**：确定性数值验证（`scripts/peel-verify.mjs`，5 投影 10° 网格）+ 对抗式独立验证（3 个怀疑者各写自己的 node 脚本，0.25°/1° 细网格、t 步长 0.001、S∈[1,100]、逐顶点回归）+ 1 个综合。结论：方案 B（含三个修正项）在墨卡托/等距柱状/圆锥上几何性消除穿模，方位投影穿模为投影固有且不回退。

## 11. 未来可选优化（本期不做）

**背面切口（move the seam to the back）**——评审中提出、本期搁置的替代思路，记录于此防丢失。

- **现状**：切口（UV 接缝）在 `lon=±180°`（−x 左轮廓），由 `SphereGeometry` 参数化涌现，非刻意。穿模的本质是**只有接缝列**要从球背面同一点分别去往地图两端 ±π，横扫正面中心；其它经度的凹陷都发生在背面（被遮挡）。故**接缝在哪条经线 = 穿模在哪个区域可见**。
- **思路**：把接缝挪到 `lon=+90°`（−z 正对相机背面），接缝列改走后半球与轮廓外 → 默认前视角看不到穿模，且**对称**（消除原"一进一出"）。
- **代价**（须先解决再采用）：
  1. 遮挡 ≠ 几何消除——OrbitControls 转到背面仍可见（需结合 Bézier 才任意视角干净）。
  2. 接缝绑死在 `SphereGeometry` UV（`phiStart`）或整体旋转，挪它会让平面图朝向/内容错位，要连带处理（球态旋转、平面态校正）。
  3. 最终地图切口落在 lon≈+90°（太平洋居中），非默认 ±180°。
- **潜在收益**：与 Bélixir 正交。组合"背面切口 + Bézier"可让本 spec 最大残留（§8 残留①赤道接缝单顶点撕裂）落到背面遮挡区，或使 Bézier 更温和。
- **决策**：本期用 §3 的 ±180° + Bézier（几何鲁棒、标准地图）。背面切口留待后续——若实机发现赤道接缝残留不可接受，或想简化 Bézier，再评估此方向，**并先做 mesh 级可见性数值验证**（接缝列在轮廓外 |x|>1 的"外翻"部分是否算穿模需确认）。
